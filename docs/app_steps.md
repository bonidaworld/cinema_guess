# Подключение приложения к PostgreSQL

Этот документ раньше описывал план подключения базы. Основные шаги уже реализованы: приложение подключается через `pg`, игровые API читают `app.v_frames_ready`, а кадры выдаются из локального каталога WebP через API-маршрут. Актуальное описание архитектуры и оставшихся задач находится в [`project_status.md`](project_status.md).

## Настройка локальной среды

1. Установите Node.js и npm.
2. Подготовьте PostgreSQL с необходимыми схемами, данными и представлением `app.v_frames_ready`. SQL-файлы проекта находятся в `db/`; справка по схеме и Supabase — в [`../supabase/README.md`](../supabase/README.md).
3. Создайте корневой `.env` с `DATABASE_URL` и `FRAMES_WEBP_DIR`, указывающими на вашу базу и каталог готовых WebP-файлов. Не добавляйте секреты в Git.
4. Установите зависимости и запустите приложение:

```powershell
npm install
npm.cmd run dev
```

`npm.cmd` обходит блокировку PowerShell для скрипта `npm.ps1` без изменения execution policy.

## Проверка вручную

1. Убедитесь, что база доступна и `app.v_frames_ready` содержит готовые кадры.
2. Убедитесь, что WebP-файлы доступны по путям, записанным в базе и разрешённым каталогом `FRAMES_WEBP_DIR`.
3. Откройте приложение и начните игру.
4. Проверьте загрузку кадра, отправку ответа, показ результата и переход через все пять раундов.

Автоматизированного теста этого сценария пока нет. Скрипты обновления базы и обработки ассетов описаны в [`../scripts/README.md`](../scripts/README.md), а общее описание запуска — в [README](../README.md).
