# Оценка вертикального среза

CinemaGuesser уже представляет собой рабочий однопользовательский прототип: меню → загрузка кадра → выбор времени → проверка ответа → следующий раунд → итоговый счёт. Сейчас приложение читает готовые кадры из PostgreSQL, а не из старых TypeScript-массивов.

## Реализовано

| Область | Текущее состояние |
|---|---|
| Интерфейс | Next.js, React и TypeScript; меню с WebGL-фоном; экран игры и итогов |
| Игровой цикл | Пять раундов, выбор времени ползунком с шагом в секунду, общий счёт |
| Выдача кадров | `GET /api/round` выбирает случайный кадр из `app.v_frames_ready`; браузер передаёт ID использованных кадров, чтобы исключить повторы в текущей игре |
| Проверка ответа | `POST /api/guess` читает правильный таймкод на сервере, валидирует ответ и считает очки |
| Изображения | `GET /api/frame-image/[framePublicKey]` обслуживает WebP-файл из настроенного локального каталога после проверки пути |
| Данные | PostgreSQL через `pg`; схема содержит этапы `ingest`, `imdb`, `core` и app-facing view `app.v_frames_ready` |
| Подготовка данных | Python-скрипты обновляют данные, обрабатывают изображения, ведут логи и создают резервные копии |

## Ограничения прототипа

- Сессия игры существует только в состоянии браузера. Сервер не закрепляет выданные кадры за игроком, поэтому API не обеспечивает целостность игровой сессии.
- Очки и история игр не сохраняются; аккаунтов и таблицы лидеров нет.
- Исключение повторов основано на ID, который присылает браузер.
- WebP-ассеты находятся локально вне Git; объектное хранилище не подключено.
- Автоматических unit-, API- и end-to-end тестов нет.
